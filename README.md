# Training Log

An installable workout tracker for iPhone. Log a session live with a timer, add sets and reps or cardio distance as you go, record heart rate and effort at the end, then watch consistency, strength progression and heart-rate trends build up.

**Live app:** https://jrjohnsonlloyd.github.io/training-log/

## Install on iPhone

1. Open the live URL in Safari.
2. Tap Share → **Add to Home Screen** → Add.
3. Launch it from the Home Screen. It opens full-screen and works offline after the first visit.

## Your data

By default nothing leaves the phone. Workouts are stored in the browser's storage for this app. Use Settings (gear icon) → **Share backup** to save a JSON file to Google Drive or Files, and **Restore from file** to bring it back on a new phone. Back up now and then; deleting the app deletes its data.

## Cloud sync (optional)

Settings → **Cloud sync** copies the same backup file to a private GitHub repository every time a workout or setting is saved, so the data can be read away from the phone. It is one way: the phone is the source of truth and the file `training-log.json` in the repository is overwritten with each sync. If the phone is offline, the sync waits and runs when it is back online or the app is next opened.

1. Create a private repository to hold the data (for example `training-data`).
2. On GitHub: Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token. Repository access: **Only select repositories** → the data repository. Permissions → Repository permissions → **Contents: Read and write**. Nothing else.
3. In the app: Settings → Cloud sync → enter the repository as `owner/name`, paste the token, tap **Save and sync now**.

The token is stored only in this app's storage on the phone. It is never included in the backup file or in what is synced. **Turn off** removes it from the phone.

## Food log

The **Food** tab tracks calories and macros against a daily target (Settings → Daily calorie target; 1,900 kcal by default).

- **Add food** by typing the numbers, or start typing a name: matches appear under the box as you type. Each row shows a small pack photo (or an icon for the kind of food), the name, the brand or group, the serving, and the calories on the right. Tap a row to fill the form (then pick a **Serving size** such as 1 cup, 1 piece, 100 g or 1 g and set Servings), or tap **Add** to log one serving straight away.
- **Filters** above the results: **All**, **Supermarket & Imported** (packaged products), **Dining Out** (restaurant and fast-food items) and **Whole Foods** (plain foods and home dishes).
- **What is searched, all saved in the app and usable offline:** your favourites and recent foods first; the curated lists (`data/local_ph_curated.json` and the older `food-library.json`: Filipino dishes and Philippine restaurant items, approximate values with sources); about 12,600 everyday foods and dishes from the USDA's public food tables; and about 25,900 packaged products from Open Food Facts (the Philippines, the US, the UK, Japan, Korea and neighbouring Asian markets). They are bundled as `food-db.json`.
- **Brands and barcodes:** a barcode number typed from a pack is matched against the bundled list first, with no network needed (12 or 13 digits alike, and the short 8-digit code of a small US can finds the same product as its full 12-digit code). **Find food** (or Enter) also looks up packaged products in Open Food Facts (worldwide, volunteer-entered, with pack photos) and US label data in USDA FoodData Central when the app itself has fewer than three matches; **Search brands online** does it on request. The USDA lookup works a few times an hour without a key; a free key from https://fdc.nal.usda.gov/api-key-signup pasted into Settings → *USDA food search key* removes that limit. The key stays on the phone and is not part of the backup or the sync.
- **More nutrition:** sugars, saturates, fibre and sodium are filled in when the food has them, saved with the entry, and totalled for the day. A toggle (and Settings → *Show as*) switches between **Sodium (mg)**, as on Philippine and US labels, and **Salt (g)**, as on UK labels. Sodium in mg is what is stored; salt g = sodium mg ÷ 400.
- **Recent**: the last foods you logged, one tap to log the same amount again.
- **Favourites**: tap *Favourite* on any entry, then log it again with one tap.
- **Photo for Claude / Ask Claude to estimate**: for meals you cannot look up. The photo (shrunk to 1280 px) or the description goes to the private data repository and the entry shows as *Pending*. A scheduled Claude task reads pending entries about every 12 hours and writes its estimates to `food-estimates.json` in that repository; the app picks them up when it opens. Needs Cloud sync on. Estimates are rough: check them and use *Edit* to correct.
- Food entries and favourites are part of the backup file and the cloud sync (under `food`). Photos are stored only in the private data repository, never in this one.

## Apple Health import

`tools/apple_health_import.py` turns an Apple Health export into a file the app can restore. Nothing is uploaded anywhere; it runs on your computer with Python 3 and no extra packages.

1. On the iPhone: Health app → profile picture → **Export All Health Data**, then get the zip onto your computer (AirDrop, Files, Drive).
2. Optional but recommended: in the app, Settings → **Download backup**, so logged workouts can be matched.
3. Run:

   ```
   python3 tools/apple_health_import.py "export.zip" --backup training-log-backup-2026-10-05.json --since 2026-01-01 --units lb mi -o training-log-import.json
   ```

4. Get `training-log-import.json` onto the phone and use Settings → **Restore from file**.

The watch tends to split one gym visit into several short workouts (strength, then core, then functional) and auto-detects walks. By default the script stitches workouts that start within 20 minutes of the previous one ending into one session (`--merge-gap`), drops anything under 10 minutes (`--min-minutes`), and drops walk-only sessions under 30 minutes (`--walk-min`; use `--walk-min 9999` to leave walks out entirely). `--skip Walk 'Core training'` leaves named activities out. You can also re-run the script on a previous `training-log-import.json` to change these without re-reading the export.

What it does: workouts you logged in the app that overlap an Apple workout get their average and max heart rate filled in (and a start time, if the entry was logged by hand). Apple workouts you never logged become their own entries: runs, walks, rides and the like as cardio with distance and time, strength sessions as a timed session with no sets (Apple doesn't record sets), yoga and stretching as mobility. Ids are stable, so running it again never duplicates anything. `--since` keeps the file small; `--units` should match the app's settings.

## How it's built

A single static page (`index.html`) with no framework and no build step, a service worker (`sw.js`) for offline use, and a web app manifest. Deployed to GitHub Pages by the workflow in `.github/workflows/pages.yml` on every push to `main`.

Strength progression uses the Epley estimate: 1RM ≈ weight × (1 + reps ÷ 30). Streaks count consecutive weeks (Monday to Sunday) at or above the weekly target.

To ship a change: edit `index.html`, bump `CACHE` in `sw.js` so installed copies refresh, push to `main`. The bump is also required whenever `food-db.json` changes: that file is cached together with the app, so a new food list only reaches an installed phone when `CACHE` changes (`training-log-v16` ships the list with the step 7 Philippine repairs).

## Food data pipeline

`food-db.json` is built on a computer by `scripts/import_foods.py` (Python 3, no extra packages). It reads the sources line by line into a small SQLite database (`data/foods.sqlite`, not committed; its table and versioned migrations are in `scripts/food_schema.py`), removes duplicates, and writes the file the app loads.

```
python scripts/import_foods.py --db data/foods.sqlite \
  --curated-json data/local_ph_curated.json \
  --usda-path "<Survey Foods (FNDDS) CSV folder>" --usda-path "<SR Legacy CSV folder>" \
  --off-path "<Open Food Facts export, en.openfoodfacts.org.products.csv or .csv.gz>" \
  --export-app food-db.json --built 2026-11-22
```

- **Sources and priority:** 1 = the curated list, 2 = USDA FoodData Central (https://fdc.nal.usda.gov/download-datasets, public domain), 3 = Open Food Facts (https://world.openfoodfacts.org/data, Open Database Licence). When two rows share a barcode, or the same name and brand, the higher-priority row is kept; it inherits the other row's pack photo.
- **Open Food Facts rows** are kept only when tagged for the Philippines, the United States, the United Kingdom, Japan, South Korea, or one of seven neighbouring markets (Thailand, Malaysia, Singapore, Indonesia, Vietnam, Hong Kong, Taiwan), which share the one region code `AS`. A product tagged only for those seven goes to the Asia pool whatever its barcode, unless the barcode is Japanese or Korean (then it stays in that pool); it never replaces a Philippine, American, British, Japanese or Korean record of the same product, and a Philippine product is never marked `AS`. Every Philippine-tagged product is bundled, except the few read by hand and found wrong (`KNOWN_WRONG_PH`) and plain oils carrying a spoonful's figures; the others are limited to the most-scanned of each market (`--off-quota`, default `US=12000,UK=2500,JP=3500,KR=2500,AS=1500`) so the file stays small enough for a phone. A product from another market whose numbers look wrong (a label typed per serving, calories that do not fit the product's own protein, carbs and fat, a dry-coffee figure on coffee, a shampoo, or one of the few rows listed by barcode in `KNOWN_WRONG` after being read by hand) is kept in the database but not bundled; a believable record of the same product takes its place when there is one. British supermarket packs that are tagged United States wait for the United Kingdom pool. Anything left out is still found by the online lookup.
- **Japan, Korea and the neighbouring markets** have checks of their own, because their labels are often typed per pack, per piece or per bottle: crisps, biscuits, Pocky, KitKat, cereal and protein bars, breakfast cereals, peanut butter, candy and mints, hard cheese, miso and gochujang, seaweed snacks, nori sheets and dried seaweed, plain chocolate and nuts with too few calories, instant noodles carrying their made-up (with water) figures, soft drinks, juices, milk coffees, soy, oat and plain milks and sports drinks with a can's or a bottle's calories, 3-in-1, latte and milk tea powders with one sachet's figures, and foods at 0 kcal (an oil at 0 kcal too) are kept out of the bundle (reasons `dense_low`, `drink_high`, `mix_low`, `zero_food`; the US per-serving test also runs on the neighbouring markets as `per_serving_as` and `per_bottle_as`, except on a serving of 80 to 125 g, coconut milk and ice pops). So are biscuits under other names (Bisco, Calorie Mate, rusks, brownies), bread and buns, Japanese sweets, oats and bran flakes, protein and amino-acid powders, plain eggs (also over 220 kcal), honey, mirin and cooking sake, Worcestershire-type sauces, dried squid and fish, natto and dry instant-noodle packs with too few calories, infant formula and supplements (`not_food`), and Western supermarket brands or short codes that only read as Korean (a Calvé peanut butter, a Lidl cheese) never enter these three pools. A crisp, biscuit, chocolate, nut, bar, cereal or peanut butter pack, or one of the kinds just listed, whose stated serving explains its too-few calories is re-based on that serving instead (the numbers become per 100 g, marked *approximate*, and the serving opens first). In the bundle only, these three pools get Latin brand names for common Japanese, Korean and Thai brands (`株式会社 神戸物産` is written Kobe Bussan, `7-11` is 7-Eleven and is also found by typing "seven eleven"), names without a shop's item code, the pack size or a brand repeated at the end (`Udon - Nissin - Nissin` becomes `Udon - Nissin`), serving labels in English (`1袋(80g)` becomes `1 pack (80 g)`), and instant noodles, drink sachets, yogurt cups, burgers, onigiri, ice creams, instant soups, stock cubes and other single packs or spoon foods open on their own serving, while a sauce bottle or a litre of milk given as the "serving" opens on 100 g. A Japanese brand in the table is only read when it stands by itself (`明治` is Meiji, `明治屋` is not; `日清食品` is Nissin, `日清フーズ` is Nisshin Foods). Rows with no brand named like a curated or USDA food ("Milk", "Mango") and shop listings saved as names are left out, a name mostly in Japanese script that nobody has scanned comes after every other candidate, and in the Asia pool a product that is only there for its barcode (not tagged for any of the seven markets) counts for half its scans. An 8-digit code that only looks Japanese (45... or 49..., common on American packs) counts as Japanese only when the product is tagged Japan. The US and UK pools skip a repeat (same plain name and calories) only of a Philippine row or of a US or UK pool row sold in their own market, so a Korean "Soy sauce" chosen for the Korea pool does not take the place of an American one, whatever its tags. The barcode of a product skipped as a repeat (and the barcodes merged into it) finds the row that was chosen, whose calories are the same.
- **The United Kingdom pool** (step 6). British labels are per 100 g by law, so the US per-serving tests stay off for British rows (rows tagged UK and not US, or British packs). Their own traps are kept out or repaired: a row whose calories do not fit its macros takes its calories from its own kJ figure when that fits (Weetabix at 227 becomes 366, marked *approximate*); stock cubes, stock pots and gravy stored as made up open on "100 ml made up", dry gravy granules lose a made-up serving, squash and cordial stored diluted (5 kcal or less, or 3 g of sugar or more per 100 ml) open on a diluted glass (250 ml), while a no-added-sugar concentrate keeps its own measure; bread typed per slice and breakfast cereal typed per serving are re-based on that slice or serving, or kept out when no serving explains the figure (`uk_bread_low`, `uk_cereal_low`); cappuccino, latte and hot-chocolate powders stored as made up with a dry sachet as serving (`uk_powder_made_up`), butter under 650 kcal (`uk_butter_low`), spirits outside 180 to 320 kcal (`uk_spirit_range`), ready meals that make under 160 kcal a pack (`uk_meal_low`), chocolate under 250 kcal (`uk_chocolate_low`) and rows divided by a serving of over 1.5 kg (`uk_huge_serving`) are kept out; dry pasta, rice and noodles stored cooked open on "100 g cooked" (four packs whose serving is a cooked portion, or missing, are listed by barcode in `KNOWN_COOKED_UK`); a pack sold as "4 x 125g" with no serving opens on one unit; multivitamin juices and flaxseed with CoQ10 are not taken for supplements. A British EAN-8 (an 8-digit code starting 50, such as Colman's mustard) tagged UK counts as local even when the product is sold in other countries too, as a 13-digit British code does, and a short list of famous British products (`MUST_HAVE_UK`: Jaffa Cakes, IRN-BRU, Monster Munch, Colman's English Mustard, Nando's PERi-PERi sauce, Greggs sausage rolls, Pret) is picked first for the UK pool, inside its quota. A kJ figure that is plainly wrong on two chia seed packs and an Ovaltine is not used to repair their calories (`_KJ_KEEP`), so their barcodes again find the chia and Ovaltine rows they merge into. In the bundle only, UK names lose a shop's item code, the pack size and "imp", and a name typed in capitals is written in ordinary case (short forms such as BBQ, HP and M&S stay, and so do words already in mixed case such as McLaren).
- **Repairs for every market** (step 6): a zero, diet or sugar-free soda, tea or energy drink storing its whole bottle per 100 ml is re-based on the bottle or kept out (`per_bottle_zero`; not milk coffees, with 1.5 g of protein or 0.5 g of fat per 100 ml or more, nor beers, ciders and premixes named zero); a dry instant-noodle pack (instant noodles, ramyun, mi goreng, Top Ramen, "chicken noodles"...) under 300 kcal with 3 g of fat or more is kept out (`dry_noodle`), unless its serving is a whole prepared cup; a plain cooking oil under 700 kcal is re-based on its spoon-sized serving or kept out (`oil_low`, Philippine rows included); a drink or single pack of the Japan, Korea and Asia pools with no serving opens on its bottle, can or pack from the pack size; a portion over 1,000 g is never the one the app opens on. Rows read by hand are listed by barcode: `KNOWN_WRONG` (other markets) and `KNOWN_WRONG_PH` (Philippine rows, left out of the Philippine part; `KNOWN_TWIN` points a left-out barcode at a believable row of the same product), and `KNOWN_PER_PACK` re-bases rows whose label was typed for a known serving or pack, only while the row still carries the calories read as wrong (so a label corrected later at Open Food Facts is not divided again). On the Philippine shelf these lists hold 3-in-1 coffee, chocolate-drink and milk powders and drink mixes stored with one sachet's or one made-up glass's figures (re-based on the sachet when its weight is known, as for Kopiko Black Twin and Great Taste White, otherwise left out) and a light soda carrying the regular drink's figures (Coke light). `KNOWN_WRONG` and `KNOWN_WRONG_PH` together are capped at 200 barcodes (160 until step 7). The wrong-pool rule spares Western shops' own products with a real Asian barcode (Aldi China, Tesco Malaysia).
- **Philippine rows typed per pack or per serving** (step 7). Many Philippine records carry one pack's or one serving's figures in the per-100 g boxes ("lm chicken 55g" at 250 kcal, "eden original 45g" at 90, Lady's Choice at 66). `ph_pack_fix` finds the kind of food from the name, brand and categories (`PH_KINDS`: noodles, chips, biscuits, snack cakes, canned meat and fish, bacon, mayonnaise, powders, sauces and about thirty more, each with the calories its real labels fall in) and, when a row stored per 100 g is outside its kind's range, re-bases it on the first weight that brings it in: the record's serving, the first weight written in the serving text, the pack weight in the name, then the quantity. The weight must be 5 to 89 g (the rule only scales up; a family pack is never used), the calories must agree with the row's own protein, carbs and fat, protein, carbs and fat together must stay at or under 100 g per 100 g, and cheese, bacon, canned fish and canned meat stay under their carb or protein caps. A row whose per-100 g figures Open Food Facts already worked out from the record's own serving (Argentina corned beef at 132.142857 kcal and 12.5 g protein is 74 kcal and 7 g for its 56 g serving) is per 100 g already and is never re-based; a macro the importer worked out itself from the calories is left out of that test. Two Purefoods rows whose per-100 g figures were doubled by hand from a 50 g serving (whole figures, which that test cannot see) are named in `PH_LEAVE_AS_IS` and left as they are. After a re-base, a fibre figure above carbs + 5 g or above 40 g per 100 g is dropped. A re-based row is marked *approximate* and opens on that weight with a plain label ("1 pack (55 g)", "1 serving (56 g)", "1 tbsp (15 g)", or the label's own words, "2 tbsp (32 g)"); 100 g stays available. Rows above their range are never divided down. Coffee, milk, chocolate and tea powders under 250 kcal carrying a made-up glass's figures with no sachet weight that explains them (`powder_made_up`) and dry foods at under 5 kcal (`zero_dry`, Ginisa Mix at 0) are left out of the Philippine part. Measured by two readers on all 5,081 Philippine candidates (the first version, with broad ranges and any weight, was wrong about 30 times in 101; the tuned rule's changes were read one by one). In the shipped list the rule re-bases 34 rows (two of them brought back), `KNOWN_PER_PACK` 7 more (Bear Brand Adult Plus stored as the made-up glass, Nanyang kaya, Knorr Goto Mix, Anchor Milk, Leslie's corn crunch, 555 fried sardines, San Marino), 53 wrong rows with no sure weight join `KNOWN_WRONG_PH` (Eden at 495 and 600, Star margarine at 367, UFC banana catsup, Gatorade at 50, Century Tuna Flakes in Oil at 106, Sky Flakes at 183 a serving, Mr. Cookie at 313, UFC banana catsup at 54, 555 Tuna Adobo at 89, Creamline Jumbo Cone at 70 ...; `KNOWN_TWIN` sends the UFC and 555 barcodes to a right row of the same product), and Nova Multigrain, Nestea Lemon Cucumber and Anchor Milk leave it, repaired. Three repaired rows now merge into a believable twin, whose barcode then finds it.
- **Shipped list:** exported with `--off-quota "US=11000,UK=2389,JP=3000,KR=2000,AS=2400"` (38,452 rows, 6,474,049 bytes: 62 curated, 12,613 USDA, then the pools in the order PH 4,988, US 11,000, UK 2,389, JP 3,000, KR 2,000, AS 2,400; the file must stay at or under 6,500,000 bytes). The full import command above writes the same file; a later export from the same database may differ by a row, because an export run merges a few repeats in the database.
- **Search order:** a packaged product from another market (not tagged Philippines, no 480 barcode) loses one point, and two more when the words typed are an everyday food the reference tables know ("ketchup") or when a Philippine product's name or brand begins with the words typed ("milo", "kopiko", "robinsons"), so Philippine products come first for everyday words and Philippine brands while a brand search ("buldak", "pocky") still leads with that brand. A product name with only a pack size after the words ("milo 24g") counts as named as typed. When a search finds fewer than three rows, a word of five letters or more typed with one letter wrong ("chiken", "brocoli", "nutela") or in the other spelling ("yoghurt") is corrected to the word the list knows best, and the rows found that way follow the ones found as typed. A word the list already knows is left alone ("bihon", "tango"), unless it is in only one or two names next to a word sixty times as common ("chiken" against "chicken"); whether **Find food** goes online depends only on the rows found as typed.
- **Clean-up rules:** values are per 100 g; kilojoules become calories (÷ 4.184) when calories are missing; salt becomes sodium (g × 400 = mg) when sodium is missing; rows with no name, no calories, or impossible numbers (more than 100 g of a nutrient per 100 g) are dropped. Baby foods and infant formulas are left out.
- **Curated list:** `data/local_ph_curated.json` is the list to grow. Copy an entry, fill it in, say whether the numbers are for the serving or for 100 g, mark `basis` honestly (`official`, `database` or `estimate`), then run the command above and commit the new `food-db.json`. A curated entry hides an older `food-library.json` entry when its name, or one of its `aka` names, is the same.

Tests (no downloads needed; they use the small made-up files in `tests/fixtures`):

```
python -m unittest discover -s tests -p "test_*.py"
python tests/run_ui_smoke.py
python tests/run_ui_smoke.py --db-file tests/fixtures/food-db.v1.sample.json
python tests/run_ui_smoke.py --suite v2
python tests/run_ui_smoke.py --suite ranking --db-file "<a real food-db.json with packaged products>"
```

The first checks the import rules and the database migration. The others drive the app itself in headless Chrome: the second and third prove that food data saved by the previous version still loads and is left untouched (with the current file and with an old-format one), the fourth checks filters, photos, barcode lookup and the sodium/salt toggle. The last checks the order of search results on a large real food list (plain foods before same-named products, curated entries first, restaurants by name, brands, plurals, accents, short US barcodes); it skips itself when the list has fewer than 20,000 rows.
